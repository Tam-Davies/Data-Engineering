# Weather Forecast Accuracy Project

This Bash proof of concept compares a recorded weather observation with the previous day's forecast. It retrieves weather data from [wttr.in](https://wttr.in/), stores the values in a log, calculates an error and accuracy label, and reports the minimum and maximum absolute error for a seven-day sample.

## Project Files

- `rx_poc.sh` - Retrieves the current temperature and tomorrow's noon forecast, then appends a record to `rx_poc.log`.
- `fc_accuracy.sh` - Converts records from `rx_poc.log` into `historical_fc_accuracy.tsv` and assigns an accuracy label.
- `weekly_stats.sh` - Calculates the minimum and maximum absolute forecast error from the last seven rows of `synthetic_historical_fc_accuracy.tsv`.
- `rx_poc.log` - Input log for the live proof of concept.
- `historical_fc_accuracy.tsv` - Accuracy results generated from the live log.
- `synthetic_historical_fc_accuracy.tsv` - Sample data used by the weekly statistics script.
- `scratch.txt` - Temporary values generated by `weekly_stats.sh`.

## Requirements

Run the scripts in Bash on Linux, macOS, Git Bash, or WSL. The scripts use common command-line tools:

- `curl`
- `grep`
- `cut`
- `tail`
- `date`

The machine running the scripts also needs internet access to `wttr.in`.

## Run the Live Collection

The `city` environment variable is required by `rx_poc.sh`. Set it before running the script:

```bash
cd weather_forcast_project
export city=Casablanca
bash rx_poc.sh
```

The script prints the observed temperature and forecast temperature, then appends a tab-separated record to `rx_poc.log`. It also writes the raw weather response to a file named `weather_report`.

The timestamp is recorded using the `Morocco/Casablanca` timezone. The script currently uses this timezone regardless of the city supplied.

## Calculate Forecast Accuracy

Run the accuracy script after collecting one or more records:

```bash
bash fc_accuracy.sh
```

This recreates `historical_fc_accuracy.tsv` with the following columns:

```text
year  month  day  obs_temp  fc_temp  accuracy  accuracy_range
```

The error is calculated as:

```text
accuracy = observed temperature - forecast temperature
```

The label is based on the absolute error:

- `0-1` degrees: `excellent`
- `2` degrees: `good`
- `3` degrees: `fair`
- `4` degrees: `poor`
- More than `4` degrees: `very poor`

## Calculate Weekly Statistics

The weekly script currently reads the last seven rows from the bundled synthetic dataset:

```bash
bash weekly_stats.sh
```

Example output:

```text
minimum absolute error = 0
maximum absolute error = 5
```

It also overwrites `scratch.txt` with the seven extracted error values. To use a different dataset, update the input filename in `weekly_stats.sh`.

## Suggested Workflow

```bash
export city=Casablanca
bash rx_poc.sh
bash fc_accuracy.sh
bash weekly_stats.sh
```

Run `rx_poc.sh` regularly, such as once per day, before rebuilding the accuracy file. The current scripts do not provide scheduling, cleanup, error handling for unavailable API responses, or protection against duplicate records.

## Current Limitations

- `city` is not given a default, so omitting it produces an invalid weather request.
- The raw response file `weather_report` is overwritten on every collection run.
- Temperature parsing depends on the text layout returned by `wttr.in` and may break if that format changes.
- `fc_accuracy.sh` overwrites the historical output instead of appending to it.
- The weekly report assumes at least seven rows and uses only the synthetic dataset by default.
- The scripts use shell word splitting when reading values, so they are intended for the current simple TSV format.
